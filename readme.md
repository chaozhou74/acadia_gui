# acadia_gui
A graphical interface for browsing experiment data generated by acadia (will expand to a generic data browser in the future)

---

## Principles
- The Runtime class should have **one** data processing method tagged with `@annotate_method(is_data_processor=True)`,  
  which prepares the data needed for plotting and stores the processed results in class attributes. Plot methods then **do not** need to take explicit data inputs.

- On each data poll, the GUI will run the tagged data processing method, and then generate plots using Runtime methods  
  tagged with `@annotate_method(plot_name=...)`.

- Plots are remade everytime in live plot, so the plotting functions can be written in *straightforward* ways, just like
  normal matplotlib code.

- The old plot is cleared every time, and new plots are made on existing plot axes. so there shouldn't be leakage or duplicated plots.

- Even if there is any leakage or gui just somehow crushes, since the plotting is a separate
  process, it won't hurt the running runtime, and data will still be saved.
  can even restart the gui when it breaks, and plot update will continue from there

---

## Runtime Method Requirements

To generate live plotting, the Runtime class must define:

- **One data processing method**
	- Decorate it with `@annotate_method(is_data_processor=True)`.
	- This method should **process raw data** that are necessary for the plot generation, and **store the results** in class attributes.
	- It should **return `completed_iterations`** (an integer), so the GUI can use that to generate the progress bar.
	- Can take keyword arguments. The GUI will inspect the method arguments and provide entry fields in the plot window.
		- Arguments with typehint `Bool` will become checkboxes.
		- Arguments with typehint `Literal[...]` will become dropdown menus.
        - More specialized input widgets can be made with the `Annotated` type hint. Check the examples for details. 
		- Other types will use generic text input fields.


- **One or more plot methods**  
  - Decorate each with `@annotate_method(plot_name=..., axs_shape:Optional[Tuple]=(1,1))`
  - A plot method must accept either:
    - `axs`: an (array of) pre-allocated Matplotlib axes (via `plt.subplots`) based on `axs_shape`, **or**
    - `fig`: a Matplotlib `Figure` object, giving the plot method full control over layout using `fig.add_subplot()` or `fig.add_gridspec()`.
  - If `axs` is used, the GUI prepares axes using the specified `axs_shape`. For multi-axes layouts, this must be set accurately.
  - If `fig` is used, `axs_shape` is ignored and the method is responsible for creating its own layout.
  - Plot methods should not take explicit data inputs; they should access class attributes populated by the processing method.
  - Like the processing method, they may accept keyword arguments and the GUI will automatically generate input fields for them.

    **Examples**:

    - `axs`-based layout (for simple grids):
    
        ```python
        @annotate_method(plot_name="summary", axs_shape=(1, 2))
        def plot_summary(self, axs=None):
            from acadia_qmsmt.plotting import prepare_plot_axes
            fig, axs = prepare_plot_axes(axs, axs_shape=(1, 2))
            axs[0].plot(self.iq_trace_amp)
            axs[1].plot(self.iq_trace_phase)
            return fig, axs
        ```

    - `fig`-based layout (preferred for custom or asymmetric layouts):

      ```python
      @annotate_method(plot_name="asymmetric_layout")
      def plot_asymmetric(self, fig=None):
          fig = fig or plt.figure()
          gs = fig.add_gridspec(3, 3, height_ratios=[1, 2, 1], width_ratios=[1, 1.3, 1])
          ax_left = fig.add_subplot(gs[:, 0])
          ax_middle = fig.add_subplot(gs[1, 1])
          ax_right = fig.add_subplot(gs[:, 2])
          ax_left.plot(self.raw)
          ax_middle.plot(self.kernel)
          ax_right.plot(self.output)
          return fig, (ax_left, ax_middle, ax_right)
      ```

## Getting started

- **Installation**
	- Activate the Python virtual environment for acadia, then cd to the acadia_gui folder and run:
	  ```bash
	  pip install -e  .
	  ```

- **Add the app to the application launcher**
	- **Native Linux** (Ubuntu 22+): nothing to do — the launcher entry is installed
	  automatically the first time you start the GUI, and the app appears in your
	  application menu / dock. (You can re-run `acadia_gui --install-desktop` to refresh
	  it, e.g. after moving the virtual environment.)
	- **WSL**: run this once after installing, then restart WSL:
	  ```bash
	  acadia_gui --install-desktop   # asks for sudo once
	  ```
	  ```
	  wsl --shutdown                 # from Windows; relaunch afterwards
	  ```
	  The app then appears in the Windows Start Menu (as `Acadia Data Browser (<distro>)`)
	  with a working launcher and taskbar icon.

- **Starting the gui**
	- Once installed, an "entry point" called acadia_gui will be available in the virtual environment. So gui can be
	  simply launched by running
	  ```bash 
	  acadia_gui -r <path_to_root_data_folder> 
	  ```
	  Make sure to run this in a terminal where the virtual environment is activated.

	  `-r <path_to_root_data_foler> ` is optional, if not provided, the home directory will be used as root data path.
	- See `acadia_gui.apps.acadia_gui_cli` for more options.

## Trouble shooting
-  **Error loading 'xcb' Plugin**

   > **Note:** On WSL the app now defaults to the **Wayland** backend, so this error
   > should no longer occur out of the box. The fix below is only needed if Wayland is
   > unavailable and you must fall back to `xcb` (e.g. you set `QT_QPA_PLATFORM=xcb`
   > yourself, or run on a non-WSLg setup).

   When running for the first time on WSL, a common error is:
    ```
	qt.qpa.plugin: Could not load the Qt platform plugin "xcb" in "" even though it was found.
	This application failed to start because no Qt platform plugin could be initialized. Reinstalling the application may fix this problem.
	Available platform plugins are: eglfs, linuxfb, minimal, minimalegl, offscreen, vnc, wayland-egl, wayland, wayland-xcomposite-egl, wayland-xcomposite-glx, webgl, xcb.
	```

   This indicates that WSL is missing some necessary libraries to render Qt GUIs.

   To fix this, **exist the virtual environment (if active) first with `deactivate`**

   Then, install the required XCB-related libraries in the WSL terminal.
    ```bash
    sudo apt install libxcb-xinerama0
    ```
    
   After installation, re-enter your virtual environment and try running the GUI again.

   If this still doesn't work, try installing the full xcb related packages
   ```bash
    sudo apt-get update
    sudo apt-get install -y \
      libxcb1 libxcb-icccm4 libxcb-image0 libxcb-keysyms1 libxcb-randr0 \
      libxcb-render-util0 libxcb-shape0 libxcb-shm0 libxcb-sync1 libxcb-util1 \
      libxcb-xfixes0 libxcb-xinerama0 libxcb-xkb1 libxkbcommon-x11-0 \
      libgl1 libegl1
   ```
